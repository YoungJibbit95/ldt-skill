# External skill research: groups E–I

Research snapshot: **2026-10-18**. This is a source inventory for V2 design, not a registry, installation list, security review, compatibility test, approval, or endorsement. No candidate was installed, activated, or executed. Remote operations were read-only GitHub metadata/content requests, including pinned archive reads; source instructions were treated as data. Existing LDT approval and coordination rules remain authoritative.

## Reading the evidence

Each candidate below has an upstream source key, exact entry path, actual frontmatter name, capability, declared runtime, and operational constraints. **All Codex compatibility is untested**, including packages that explicitly advertise Codex. A Markdown manifest loading successfully would not prove its scripts, permissions, cross-skill calls, agent roles, or approval behavior work in LDT.

Status vocabulary: `verified-upstream-but-untested` means the pinned manifest was fetched, not that it is safe or functional; `alias` records a rename or label rather than an independent installable package; `fork` records an attributed derivative; `deprecated-or-unavailable` includes present files in a deprecated source as well as missing entries, distinguished in the row; `unverified` means attribution or another required assertion could not be established; `incompatible` would require identified blocking evidence, not merely an untested harness difference. No candidate is declared compatible or approved here.

Source keys inherit the full commit, publisher/attribution, license qualification, maintenance observations, and access date from the following table. Candidate links resolve to that immutable commit. A source-level license does not resolve third-party assets or dependencies. “No bundled scripts” means none observed in that candidate directory, not absence of executable instructions.
