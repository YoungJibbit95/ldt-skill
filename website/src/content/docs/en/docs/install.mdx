## 1. Check prerequisites

Set up Codex using its [official quickstart](https://developers.openai.com/codex/quickstart/) and sign in there. The following steps install the skill, not Codex itself. Use a terminal on the machine where Codex accesses your project files.

```sh
git --version
python --version
```

Validation helpers need **Python 3.10 or later**. On macOS/Linux, the command is often `python3`; Windows may offer `py -3`. Use the command that works on your machine below. No `pip` installations are needed. The website also describes newer local extensions that are not yet included in the published GitHub pin `9a062eb`. Choose the public revision using the policy below.

## Choose a version before copying

The short prompt asks the agent to handle this decision. For manual setup:

1. Check [Releases](https://github.com/YoungJibbit95/ldt-skill/releases) at installation time. Prefer the latest non-draft, non-prerelease release whose skill package and relevant checks you can verify. Review its notes and compatibility; a tag alone is not verification.
2. If no verified stable release is available, say so and offer a specific verified development revision before proceeding. As of **20 October 2026**, there are no releases. The public development revision [`838a2e1`](https://github.com/YoungJibbit95/ldt-skill/tree/838a2e1376a0b3e44931c54310be95d253380b1a) contains the same skill package as the documented `9a062eb` source. It is a fallback, not a stable release or a finished V2.
3. Replace `SELECTED_TAG_OR_COMMIT` below with the chosen release tag or full development commit (`838a2e1376a0b3e44931c54310be95d253380b1a` for that fallback). Resolve it to an immutable commit, inspect its skill instructions, validate the complete package, and retain `INSTALL_REVISION.txt` with your project's installation notes. Stop on failed checks; do not silently substitute `main` or a prerelease.
4. If an installation already exists, compare it and preserve local changes. The copy commands below stop instead of overwriting it. Follow **Update** only after choosing that update.

The published skill handles discovery, architecture proposals, optional specialist work, checks and saved project context. Structured intake, architecture-team/task-contract helpers and the new runtime are still unpublished development. Automated release selection is not currently provided by the distributed skill; the installing agent must follow the policy above. The [guide](/ldt-skill/en/docs/guide/) explains the supported workflow.

## 2. Retrieve a named source revision

Run the appropriate block in a working folder outside your target project. The name `ldt-skill-source` must not already exist there. Use the version selected above. The checkout stops if you leave the placeholder unchanged. The exact resolved commit is recorded outside the skill folder.

<Tabs>
  <TabItem label="Windows · PowerShell">
```powershell
git clone https://github.com/YoungJibbit95/ldt-skill.git ldt-skill-source
if ($LASTEXITCODE -ne 0) { throw 'Clone failed.' }
git -C ldt-skill-source checkout --detach SELECTED_TAG_OR_COMMIT
if ($LASTEXITCODE -ne 0) { throw 'Source revision unavailable.' }
$resolvedRevision = git -C ldt-skill-source rev-parse --verify 'HEAD^{commit}'
if ($LASTEXITCODE -ne 0) { throw 'Cannot resolve source commit.' }
$resolvedRevision | Set-Content -LiteralPath 'ldt-skill-source/INSTALL_REVISION.txt' -Encoding utf8
$skillSource = (Resolve-Path -LiteralPath '.\ldt-skill-source\.agents\skills\architect-dev-team').Path
```
  </TabItem>
  <TabItem label="macOS / Linux · Bash">
```bash
git clone https://github.com/YoungJibbit95/ldt-skill.git ldt-skill-source &&
git -C ldt-skill-source checkout --detach SELECTED_TAG_OR_COMMIT &&
# Continue only after a successful checkout.
git -C ldt-skill-source rev-parse --verify 'HEAD^{commit}' > ldt-skill-source/INSTALL_REVISION.txt &&
skill_source="$(cd ldt-skill-source/.agents/skills/architect-dev-team && pwd)"
```
  </TabItem>
</Tabs>

Before copying, read at least `SKILL.md` and its linked workflows. The historical [reference source](https://github.com/YoungJibbit95/ldt-skill/tree/9a062eb9de0990ce1074dd677d26e5a528ee14a0/.agents/skills/architect-dev-team) remains available for comparison.

## 3. Choose the scope

<Tabs>
  <TabItem label="For one project">

In the same terminal, change to your **existing target project**. The source variable you set above remains available. The destination is `.agents/skills/architect-dev-team` in your project root.

**Windows · PowerShell** — replace the example path:
```powershell
Set-Location -LiteralPath 'C:\path\to\your\project'
$skillDestination = Join-Path (Get-Location).Path '.agents\skills\architect-dev-team'
if (Test-Path -LiteralPath $skillDestination) { throw 'Destination already exists. Not overwritten.' }
New-Item -ItemType Directory -Force -Path (Split-Path -Parent $skillDestination) | Out-Null
Copy-Item -LiteralPath $skillSource -Destination $skillDestination -Recurse
```

**macOS / Linux · Bash** — replace the example path:
```bash
cd '/path/to/your/project' &&
skill_destination="$PWD/.agents/skills/architect-dev-team" &&
test ! -e "$skill_destination" &&
mkdir -p "$PWD/.agents/skills" &&
cp -R "$skill_source" "$skill_destination"
```

If the destination exists, copying stops. You can then version the skill folder with your project. Existing project instructions and approvals still apply.
  </TabItem>
  <TabItem label="For your personal use">

According to the [official Codex documentation](https://learn.chatgpt.com/docs/build-skills), the personal skill location is `.agents/skills` in your home directory. This makes the skill available across projects.

**Windows · PowerShell:**
```powershell
$skillDestination = Join-Path $HOME '.agents\skills\architect-dev-team'
if (Test-Path -LiteralPath $skillDestination) { throw 'Destination already exists. Not overwritten.' }
New-Item -ItemType Directory -Force -Path (Split-Path -Parent $skillDestination) | Out-Null
Copy-Item -LiteralPath $skillSource -Destination $skillDestination -Recurse
```

**macOS / Linux · Bash:**
```bash
skill_destination="$HOME/.agents/skills/architect-dev-team"
test ! -e "$skill_destination" &&
mkdir -p "$HOME/.agents/skills" &&
cp -R "$skill_source" "$skill_destination"
```

Avoid simultaneous personal and project copies of the same skill unless you deliberately want two separate versions. Codex can show both.
  </TabItem>
</Tabs>

## 4. Verify the package and discovery

Check the installed copy in the same terminal. It must include `scripts/ldt_core`.

<Tabs>
  <TabItem label="Windows · PowerShell">
```powershell
python -B (Join-Path $skillDestination 'scripts\validate.py') package $skillDestination
```
  </TabItem>
  <TabItem label="macOS / Linux · Bash">
```bash
python3 -B "$skill_destination/scripts/validate.py" package "$skill_destination"
```
  </TabItem>
</Tabs>

Expected output: **`OK package`** with exit code 0. This confirms structural package validation, not Codex discovery or approval of a development milestone.

Open your target project in Codex. Check whether `architect-dev-team` appears in the skill selector. If a running session has not discovered the new copy, start a new session or reload Codex. Then invoke it explicitly:

```text
Use $architect-dev-team. Read the project instructions and inspect this project.
Summarize the goal, current state, and open questions. Start with an
architecture proposal and a small first milestone.
```

The [first-task guide](/ldt-skill/en/docs/guide/) explains what comes next.

## Update

1. Record the currently installed commit and preserve local modifications.
2. Run `git fetch origin` in the source repository and select a **specific reviewed commit**. Compare it with your previous revision; run `git checkout --detach <COMMIT>` only in that separate source repository.
3. Copy the complete new skill into a **new temporary directory** first and validate that copy.
4. Back up the existing installation outside every `.agents/skills` directory, remove the old copy from the active skill location, and copy the verified new version to the same destination. Do not mix files from different versions.
5. Validate the installed copy again and check discovery in a new Codex session. Restore the backup if needed.

Existing project states are not automatically migrated or reapproved. Read changes to state formats and approval rules before continuing an ongoing project.

## Remove

Check the absolute path and use your file manager to remove only the installed `architect-dev-team` folder. Do not remove the parent `.agents` directory. Project state under `.architect-dev-team` is separate project data; decide separately whether to retain it. Then open a new Codex session.

## Troubleshooting

| Observation | Next step |
| --- | --- |
| Python command not found | Check `python3` or `py -3`; install Python 3.10 or later if needed. |
| `INVALID` or missing shared core | Copy the complete folder including `scripts/ldt_core`; read the exact diagnostic. |
| Skill does not appear | Check the project/user path and `SKILL.md`; open the correct project and a new Codex session. |
| Skill appears twice | Inspect personal and project copies; remove only the unwanted copy. |
| Existing project state does not match | Reconcile actual sources and evidenced decisions. Do not invent approval by editing a JSON file. |
| A tool or subagent is unavailable | Use available native workflows. The skill does not guarantee a specific integration. |

<Aside type="note" title="What verification establishes">
A package check and successful copy do not establish Codex discovery on every operating system. Platform and discovery tests are reported separately in project documentation. This guide does not claim that every Codex environment has already been exercised.
</Aside>
