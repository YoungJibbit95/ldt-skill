LittleDevTeam is a skill for Codex. It guides your agent from a request through approved architecture to a verified milestone. The skill's technical name is **`architect-dev-team`**. Use it for a new project, a substantial feature, or a complex refactor.

## How the skill works

1. **Understand:** inspect the request, project state, and actual capabilities.
2. **Plan:** define requirements and a suitable architecture proposal.
3. **Decide:** present you with a concrete proposal and observable goals.
4. **Build:** implement one approved milestone.
5. **Verify:** run relevant checks and review the result.
6. **Continue:** present the concrete result for your evaluation before the next milestone.

Lean, Balanced, and Rigorous profiles adapt effort to the task. Balanced is the default. Profiles do not change approval rules. The current development work adds structured project intake, architecture research contracts, task contracts, a project view with a start gate, and helpers for source inventory, integration, and runtime evidence. A lead coordinates and integrates; real agents run through an available harness. The skill itself does not supply an agent platform.

## What you need

- A configured, signed-in **Codex environment** that can read local skills.
- **Git** to retrieve the documented source revision.
- **Python 3.10 or later** to use the bundled validation helpers. They require no external Python packages.

The skill is a folder of instructions, references, templates, and Python helpers. It does not install a separate `ldt` application. This native workflow does not require you to put your own API key into the skill; Codex manages its own sign-in.

## Published source and ongoing development

The skill source published on GitHub is [`9a062eb`](https://github.com/YoungJibbit95/ldt-skill/tree/9a062eb9de0990ce1074dd677d26e5a528ee14a0). This website also describes newer local development work on intake, the architecture team, task contracts, pair execution, integration, and runtime. Those changes are not part of that published commit yet, so version selection must account for that limitation. This documentation does not claim a finished V2 release or blanket approval of ongoing development work.

<Aside type="note" title="Instructions and validation have limits">
Local tools check data consistency and source snapshots. They do not authenticate human decisions. Tool permissions, human approvals, and actual test results remain separate concerns.
</Aside>

Registry entries describe candidates; they do not install or activate third-party skills. There is no standalone `ldt` CLI. The new OpenCode runtime adapter is local development work; a Codex runtime integration has not been verified.
